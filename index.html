第1章 確率論 カードを引く確率を計算する

到達目標： 手札にキーカードが来る確率を厳密に計算し、ランダム効果の平均とばらつきを求め、モンテカルロで照合できる。

1.1 何を一回と数えるか

山札40枚、キーカード3枚、最初の7枚を見る。引き直しや追加ドローはまだない。カードの総数を N、キーカード枚数を K、引く枚数を n、引いたキーカード枚数を X とする。「引けた」は事象 X ≥ 1。1枚目を戻さない以上、2枚目の確率は1枚目の結果に依存する。

1.2 条件付き確率とベイズの定理

P(B｜A) は「A が起きた集団に絞った B の割合」。例えば A を「1枚目が非キー」とすると、次がキーの確率は 3/39。掛け算なら「1枚目も2枚目も非キー」は (37/40) × (36/39)。

P(A∩B)=P(A)P(B∣A) P(A\cap B)=P(A)P(B\mid A)

P(A∣B)=P(B∣A)P(A)P(B) P(A\mid B)=\frac{P(B\mid A)P(A)}{P(B)}

後半がベイズの定理。以下の数値は架空の観測値とする。A を「試合終了までに一度でもキーを引いた」、B を「勝った」とする。これは 1.3 の「初手7枚で引いた」とは別の事象である。P(A)=0.45、P(B｜A)=0.60、P(B｜Aでない)=0.40 とする。分母の P(B) は、A の場合と Aでない場合に分けて足して求める（全確率の法則）：0.45×0.60＋0.55×0.40＝0.27＋0.22＝0.49。勝った試合に占めるキー取得の割合 P(A｜B) は 0.27/0.49≈55.1%。条件の向きが逆の P(B｜A)=60% と混同しない。これはカードを差し替えた因果効果ではない。長く生き残った試合ほど多く引けるからだ。

1.3 確率分布 二項分布と超幾何分布

分布とは値ごとの確率の一覧。一定確率 p で独立な試行を m 回行ったときの成功数は、二項分布 Bin(m, p) に従う。引く枚数 n と区別するため、試行回数は m と書く。混ぜ直した山札で「1枚以上引けたか」を m 回独立に反復すると、その成功数は p≈0.4478 の二項分布になる。一方、一つの山札の中で戻さずに引いたキーカード枚数 X は超幾何分布になる。式の前に記号を一つ決める。C(a,b)（式中では縦に並べた二項係数の記法）は「a 個から順番を無視して b 個を選ぶ数」である。例：C(3,1)=3、C(40,7)=18,643,560。

P(X=x)=(Kx)(N−Kn−x)(Nn) P(X=x)=\frac{\binom{K}{x}\binom{N-K}{n-x}}{\binom{N}{n}}

P(X≥1)=1−(377)(407)≈0.4478 P(X\ge1)=1-\frac{\binom{37}{7}}{\binom{40}{7}}\approx0.4478

式の凡例：分母 C(N,n) は、n 枚の手札としてありうる組合せの総数。分子 C(K,x)C(N−K,n−x) は「x 枚をキーから、残り n−x 枚を非キーから選ぶ」手札の数。どの手札も同じ確率で出る（十分に混ぜた）ことが前提である。右の式は N=40、K=3、n=7 を代入し、少なくとも1枚の確率を余事象 X=0 から求めたもの。C(37,7)=10,295,472 なので、1−10,295,472/18,643,560≈0.4478。独立と誤って 1−(37/40)^7 を使うと、約42.1%になる。

1.4 期待値と分散

効果Aは必ず4点。効果Bは確率1/2で0点、1/2で8点。どちらも平均4点だが、Bは平均から毎回4点ずれる。期待値 E[X] は長期平均、分散 Var(X) は平均からのズレの二乗の平均。標準偏差を取れば点数の単位に戻る。

E[X]=∑xxP(X=x) E[X]=\sum_x xP(X=x)

Var(X)=E[X2]−E[X]2 \operatorname{Var}(X)=E[X^2]-E[X]^2

Aの分散は0、Bは (0²＋8²)/2−4²＝16。残り6点の相手を今ターンに倒せる確率はAが0%、Bが50%。平均値が同じでも、勝ちに必要な条件が違えば選ぶカードも変わる。

1.5 モンテカルロで理論値を照合する

正解が分かる小さな例を先に回す。毎試行、40枚から7枚を戻さずサンプルし、キーがあれば1を足す。試行を独立にリセットし、シードと試行数を記録する。少数試行でのブレはバグとは限らない。理論値から大きく外れ続けるなら、山札復元、キー枚数、重複抽選、見た枚数を点検する。

from math import comb
from random import Random

rng = Random(2026)
deck = [1] * 3 + [0] * 37
trials = 20_000
wins = sum(any(rng.sample(deck, 7)) for _ in range(trials))
expected = 1 - comb(37, 7) / comb(40, 7)
print(wins / trials, expected)

演習：キーが1枚なら7枚で引ける確率は？

解答を表示

7/40＝17.5%。3枚の場合は44.78%で、17.5%を単純に3倍した52.5%ではない。複数のキーが同じ手札に含まれるケースを重複して数えてしまうため。

第2章 数理統計 勝率と信頼区間を読む

到達目標： 推定・区間・仮説検定の役割を分け、対応のある実験にブートストラップを適用し、回帰と多重比較の落とし穴を説明できる。

2.1 母数と推定値

固定したデッキ、AI、先後、ルールのもとでの真の勝率を p、手元の W 勝 / n 試合を推定値 p̂ と書く。ここでの n は試合数（1.1 の引く枚数とは別）。独立で同じ条件の勝敗なら Var(p̂)=p(1−p)/n で、その平方根 √(p(1−p)/n) を標準誤差と呼ぶ。p は未知なので、実際の見積もりでは p̂ を代入する。n を4倍にしても、標準誤差は半分にしかならない。以後、勝率どうしの差は「ポイント」で表す。ポイントは百分率の差で、55%と52%なら3ポイント。相対的な「%増」とは区別する。引き分けを除くなら「決着した試合での勝率」に問いが変わる。勝ち1・分け0.5・負け0の得点率にするなら、二項分布の区間をそのまま使わない。

2.2 95%信頼区間と Wilson 法

勝率が端に近い場合や試行が少ない場合、p̂±1.96×標準誤差の単純な正規近似は不適切になりやすい。独立な二値データの勝率には Wilson 区間を使う。z は正規分布の分位点で、95%なら約1.96。式中の ± で下限と上限を得る。

p̂+z2/(2n)±zp̂(1−p̂)/n+z2/(4n2)1+z2/n \frac{\hat p+z^2/(2n)\ \pm\ z\sqrt{\hat p(1-\hat p)/n+z^2/(4n^2)}}{1+z^2/n}

220勝/400試合は55.0%、95% Wilson区間は約50.1%〜59.8%。95%とは「同じ手順で標本を取り直して区間を作り続けたとき、真値を含む割合の目安」。今回の区間内に真値が95%の確率である、という意味ではない。区間が狭くても、そのAIが苦手なコンボを見落とす問題は消えない。

2.3 仮説検定と効果量

変更後 B の勝率から変更前 A の勝率を引いた差 B−A を Δ とする。向きは 3.4 の実験票と同じ。帰無仮説 H₀: Δ=0 を置くと、p値は「H₀と検定の前提のもとで、観察値と同程度かそれ以上に極端な統計量が出る確率」。仮説が正しい確率ではない。有意でない結果も「差がない」の証明にはならない。

変更の判断には効果量と幅を使う。例えば +0.5ポイントでも大量の試合なら検出できる一方、+3ポイントでも幅が−2〜+8なら判断材料が足りない。「±2ポイント内なら実務上は同等」と扱いたい場合、その境界は結果を見る前に決め、等価性の問いとして設計する。

2.4 ペア比較とブートストラップ

同じシード・対戦相手・先後を使った A/B を一組にする。各組の差 dᵢ は、A負けB勝ちなら+1、A勝ちB負けなら−1、結果が同じなら0。100組中 +1 が20組、−1 が12組なら Δ̂=(20−12)/100＝+8ポイント。二つの勝率区間を引き算して差の区間を作るのではなく、差そのものを評価する。

ブートストラップは独立な組を元と同数だけ復元抽出し、平均差を何度も取り直す方法。例えば2,000回の平均差の2.5・97.5パーセンタイルを簡易区間にする。先後を入れ替えた4試合（A先攻・A後攻・B先攻・B後攻）で1シードを共有する場合は、ブロック差を d_b＝(先攻のB−A＋後攻のB−A)/2 と定める。勝ちを1、それ以外を0とする場合、d_b は −1, −0.5, 0, 0.5, 1 のいずれかになる。分けを0.5点とする得点率なら、0.25刻みも生じる。抽出は個別の試合ではなく、このシードブロックごとに行う。3.3 の s は、この d_b の標準偏差を指す。独立ブロックが少ない、差がほぼ全部ゼロのときはこの簡易法も不安定。

2.5 回帰分析と多重比較

ロジスティック回帰は log(p/(1−p)) = β₀＋β₁×変更後＋β₂×先攻＋相手別の項 のように勝率を説明する。β₁は対数オッズの変化であり、勝率ポイントそのものではない。読むときは条件を固定した予測勝率の差も出す。相手ごとに効果が違うなら交互作用を検討する。ペアの依存を無視した標準誤差は使わない。回帰だけで観測されていない交絡は消えない。

100カードを個別に有意水準5%で調べ、全てに真の効果がなければ、偽陽性の期待件数は5件。候補発見と確認を分ける。少数の確認的検定では Holm 法（p値の小さい順に α/m、α/(m−1)…と比べ最初の不棄却で止める）、探索では偽発見率の管理を検討し、上位候補は独立シードで再確認する。

演習：AとBの合計800行を独立として再抽出してよい？

解答を表示

同じ400シードで対応づけたなら不可。400組を抽出し、組の内部を崩さない。シードをまたいで相関が残る場合は、さらに上の独立単位を見直す。

参照：NIST Wilson区間 ／ NIST Bootstrap

第3章 実験計画 カード変更の影響だけを測る

到達目標： 対照・無作為化・ブロック化・交絡を見分け、効果量と検出力を先に決め、再実行可能な実験票を書ける。

3.1 まず問いを一文にする

例：「基準デッキのキー1枠を同じ役割の別カードに替えると、この二対面で勝率は何ポイント変わるか」。Aは基準デッキ、Bはその1枠だけ代替。ルール、AI、対戦相手、先後の配分、集計規則を合わせる。対照とは比較の基準。評価したいのが攻撃力だけの変更なら、カード名・同時変更・デッキ枚数も揃える。

キーを引いた試合と引かなかった試合の勝率差は別の問い。勝ちやすい試合が長引いてドロー機会が増えるなら、試合の長さの影響が混じる。観測値は診断に使い、介入の効果と呼ぶならカードの差し替え、または取得制約を明示した別実験で確かめる。

3.2 無作為化 ブロック化 共通乱数

無作為化は偏った割当を避ける手段。例えば実験の実行順を混ぜて、処理系や実行環境の時間変化と A/B を切り離す。ブロック化は対面やシードなど、比較対象ではない条件を組の中で揃え、その組の中で比較対象の A/B を変えること。同じ対面・シードで先攻の A/B、後攻の A/B を1ブロックにする。相手が毎回違うAとBを無計画に合算すると、カードより対面の難しさを測ってしまう。

共通乱数法は比較条件を揃えるためにA/Bで乱数入力を共有する。Var(B−A)=Var(B)+Var(A)−2Cov(A,B) なので、正の相関が得られた場合に精度が上がる。全用途を一つの乱数列で回すと、効果が1回増えただけで後続の山札までずれる。シャッフル・効果・AIを分け、安定した用途IDと呼び出し番号を使う。同じ用途でもイベント対応が変わる箇所は同期が崩れうるので、対応規則を検証する。

3.3 効果量 検出力 試行数

設計時に「運用上見逃したくない差」を定める。例えば勝率差+3ポイント。検出力は、指定した真の差があるときに検定がそれを検出する確率。例えば有意水準5%、検出力80%を目標にする。小さな差や大きなばらつきほど多くの独立ブロックが要る。試合数を決める前に小さな予備実験でブロック差の分散と実行時間を測る。

独立なブロック差 d_b（2.4）の標準偏差を s、検出したい差を δ、必要なブロック数を n_B とする。両側5%・検出力80%の正規近似では n_B ≈ ((1.96＋0.84)×s/δ)²。1.96 は両側5%の棄却境界に当たる標準正規分布の分位点（97.5%点）、0.84 は検出力80%に対応する分位点（80%点）。s=0.35、δ=0.03 なら (2.80×0.35/0.03)²≈1,067.1 で、切り上げて約1,068ブロック。1ブロックは4試合なので、約4,272試合になる。これは計画の目安であって保証ではない。予備実験の結果を解析仕様に反映したら、確認には新しいシードを使う。途中で有意になった時だけ止める運用は、事前に逐次設計をしない限り避ける。

3.4 実験票と読み方

  • 比較：A=元のカード、B=同じ役割の代替。効果の向きは B−A。

  • 独立単位：対面ごとに多数のブロックを用意し、各ブロックに独立シードを1つずつ割り当てる。1ブロックは、同じ対面・シードで先後×A/B を組み合わせた4試合。区間と検定はブロック差 d_b（2.4）で計算する。

  • 主指標：対面ごとの勝率差と区間。補助指標：取得率、事故率、ターン別の取得状況。

  • 追跡：ルール版、デッキ版、AI版、乱数方式とシード、引き分けの扱い、除外、実験日時。

  • 再確認：二つ目のAI方針と未使用のシード。差が大きいペアを実際のログからリプレイ。

演習：Aを全て先攻、Bを全て後攻にして100万回回したら？

解答を表示

先後と変更が完全に交絡する。精度は高くても問いに答えない。同じ対面・シードで両条件をそれぞれ先攻と後攻に置く。

第4章 対戦AI 合法手から選ぶ

到達目標： ゲーム木を描き、Minimax、α–β、Expectimax、MCTS の使い分けを説明し、相手の手札を盗み見ないベースラインAIを設計できる。

4.1 状態 行動 終端 評価

探索は「現在 → 合法手 → 次の状態」の反復。勝敗が確定した状態を終端という。終端の効用を勝ち+1、引き分け0、負け−1と置く。終端まで読めない場合は、深さの上限で盤面評価関数を使う。たとえば「自分と相手の残りHP差、次ターンの打点、手札差」の重み付き和。即時の勝ちや負けは常に別扱いにし、重みを変えたAIでも実験結果が維持されるか測る。

木を読む前に、合法手から一様に選ぶAIと「確実に倒せる手を優先する」というルールベースAIを作る。ランダムAIはルールとログの検証に便利。ルールベースAIはカード評価の最初の測定器だが、教えていないコンボには弱い。

4.2 Minimax と α–β 枝刈り

二人零和、完全情報、確率要素なしという小さなゲームを考える。自分の節では最大値、相手の節では最小値を取る。下図の数値は自分から見た評価。相手の反応まで読むと、防御は min(3,5)=3、攻撃は min(2,9)=2。最大の3を保証できる防御を選ぶ。

防御を先に調べると、MAX はすでに3を確保している。攻撃の最初の相手応手で2が出た時点で、MIN が選べる値は高くても2。次の9を調べても根の結論は変わらない。αはMAXが確保した下限、βはMINが確保した上限。α≥βなら枝を飛ばせる。手の探索順で、枝刈りの量（速さ）は変わる。ただし同じ深さと評価関数なら、根の値は変わらない。同点の手が複数あるときは、どれを返すかが探索順で変わりうる。そのため同点時の順序を明示する（4.4・5.2）。まず枝刈りなしの答えと一致することを小さな木でテストする。

4.3 Expectimax とランダム効果

偶然で分かれる節では、最良や最悪ではなく結果の確率付き平均を取る。相手の最善応手も含むなら、MAX・MIN・偶然の節を使い分ける。相手AIの行動分布が既知でそれを評価したいなら、その節を最悪応手ではなく分布で扱う。

V(schance)=∑ipiV(si) V(s_{\mathrm{chance}})=\sum_i p_iV(s_i)

「確実に4点」と「0点か8点が半々」は打点の期待値では同点。しかし残り6HPで「今ターンで勝つ」を目的にすれば、前者0、後者0.5。目的関数を先に決める。ランダム効果を常に期待打点に置き換えると、この差を落とす。

4.4 MCTS 時間をかける枝を選ぶ

分岐が多いと全探索は難しい。MCTS は選択→展開→終端までの模擬対戦または葉評価→結果の逆伝播を繰り返す。UCB の代表形は Q＋c√(ln N_p / n_c)。Q は子の平均報酬、N_p は親の訪問回数、n_c はその子の訪問回数、c は探索係数である。1.1 の山札枚数 N・引く枚数 n とは別の記号。第2項は、訪問が少ない子ほど大きくなる「まだ分からない分」の上乗せである。勝っている枝を使いつつ、未訪問や試行が少ない枝にも機会を与える。未訪問は先に試す。対戦相手の節では同じ視点の報酬をそのまま最大化せず、視点・符号を明示する。最終手は訪問回数最大など、選択中の探索式とは別の規則にできる。

時間予算は負荷で揺れる。比較や再現テストでは固定の展開回数、乱数シード、同点時の順序から始める。ランダムプレイアウトが弱い場合、試行回数を増やしても人間に近づく保証はない。

4.5 不完全情報と観測

相手の手札や山札順を知らないので、同じ公開盤面に複数の真の状態が対応する。ゲームコアは真の状態を所有し、AIには自分の手札と公開情報から作った観測だけを渡す。観測として区別できない状態で、同じ観測・シードを与えたAIの選択が変わらないことをテストする。

隠れた状態の候補をサンプルして探索する方法はあるが、候補の真の状態ごとに別の未来の手を選ぶと、本番では使えない知識で一つの戦略を評価してしまう。初期版に複雑な探索は不要。ルールベースAIで比較を回せるようにしてから、必要なら不完全情報を扱う探索を導入する。

演習：あるカードがルールベースAIでは弱く、探索型では強い。何を報告する？

解答を表示

「AI方針で効果が変わる」。両方の効果・区間を併記し、差の大きい試合を再生して、どのコンボや読みの深さで差が出たか調べる。

第5章 ソフトウェア工学 再現できるゲームコアを作る

到達目標： 状態管理、責務分離、状態遷移、不変条件、テスト、再現性を一つの設計に落とせる。

5.1 状態と責務の境界

State には双方のHP、ターン、山札・手札・捨て札、処理中フェーズ、勝敗を持つ。Unity のアニメーション状態・見た目の並びは含めない。AI は Observation と合法手を読み、ルール適用は Core だけが行う。Simulation は対戦を回してシードを割り当て、Storage は結果を書き、Python はファイルから統計を計算する。Unity でも同じコアを参照するので、視覚化のためにルールを二重実装しない。

製品固有のカード・AI評価関数・レポートは公開リポジトリを参照する側に置き、公開側から参照しない。教科書では以下の見本ルールだけを使う。

5.2 状態遷移を関数として表す

入力は状態、行動、明示的な乱数コンテキスト。返り値は次の状態とイベント。合法手でない入力は状態を変えず失敗させる。「誰の番か」「カードがその手札にあるか」「コストを払えるか」はUIでなくCoreが判定する。次の C# 9 は契約の最小イメージであり、既存リポジトリの実装名を示すものではない。

public interface IGame<TState, TMove, TObservation, TRng>
{
    TObservation Observe(TState state, int player);
    IReadOnlyList<TMove> LegalMoves(TObservation observation);
    Step<TState> Apply(TState state, TMove move, TRng rng);
    int? Outcome(TState state); // null = 継続、0 = 引分、1/2 = 勝者
}

Step は、次の状態と型付きイベント列を持つ結果型とする。TRng は、乱数の鍵と進み方を明示した型とする。Outcome は勝者をプレイヤー番号で返す。4.1 の効用（勝ち+1・分け0・負け−1）を得るには、どのプレイヤーの視点で評価するかを先に決め、その視点でこの戻り値を変換する。履歴が同じでも内部の辞書順やスレッドの完了順で同点手を決めると結果がずれるので、安定した明示順を決める。

5.3 不変条件とテスト

不変条件は妥当な状態で常に成り立つ条件。カード保存則は「生成・追放などのルールがない場合、山札＋手札＋盤面＋捨て札で総数一定」。生成を許すなら、生成・消滅をイベントで追跡して保存則を言い換える。終端からは次の合法手が出ない。HPを0で止めるルールなら負の値を返さない。

  • 単体テスト：残り6HPに4点を与えると残り2HP。8点なら終端。

  • 境界テスト：空の山札、ちょうど0HP、終端への連続入力、不正な手札ID。

  • 性質テスト：固定シードから合法手を多数生成し、全遷移で不変条件を確認する。

  • リプレイテスト：初期状態・行動列・シードを保存し、終端結果とイベント順を再計算して一致させる。

  • 並列テスト：実行ワーカー数を変え、試合IDで並べ直した結果を一致させる。並列化は試合間、試合内はルール順。

5.4 乱数と記録

乱数は「実験シード・乱数を共有する範囲のID・用途ID・安定したイベント番号」から作る。A/Bでシャッフルを共有する場合は、各試合固有のIDではなく、両方に共通のペアIDと対象の側を使う。別々にしたい用途にだけ条件ラベルを加え、ログ用の試合IDは別に持つ。言語処理系の汎用ハッシュや乱数の将来互換を前提にせず、アルゴリズムとバージョン、固定入力の出力例を残す。日時、共有グローバル乱数、完了順は結果に影響させない。

結果には実験ID、試合・ペアID、先後、ルール版、デッキとAIの版、乱数版、シード、勝敗と終了理由、必要なイベントを保存する。実験条件のJSONと試合結果は別に持ち、分析スクリプトはどの条件を読んだかを結果に含める。リプレイに非公開情報が必要でも、公開レポートに手札やカード原本を出さない。

演習：ワーカーを1→8にすると結果が変わる。どこから調べる？

解答を表示

共有乱数、ワーカー番号を含むシード、同点の列挙順、ログのマージ順。試合IDが同じ1試合を個別に再生し、最初にズレたイベントを突き止める。

第6章 統合実習 キーカード依存を測る

ゴール： 勝率の変化が本当に変更に由来するか、再現できる形で説明する。

6.1 最小の実行例

まず1手で終わる極小の見本で、条件違いを同じ入力で比べる。相手の残りHPは4か6が半々。変更前Aは固定4点、変更後Bは0点または8点が半々で、HPと効果の乱数は独立とする。勝ちは打点が残りHP以上のとき。AはHP4のときだけ勝ち、Bは8点のときだけ勝つ。全体ではどちらも50%だが、HP4の相手にはBが−50ポイント、HP6には＋50ポイント。合算すると相性の変化が消える。

from itertools import product

pairs = [
    (hp, int(4 >= hp), int(damage >= hp))
    for hp, damage in product((4, 6), (0, 8))
]
assert pairs == [(4, 1, 0), (4, 1, 1), (6, 0, 0), (6, 0, 1)]
for hp in (4, 6):
    diffs = [b - a for h, a, b in pairs if h == hp]
    print(hp, sum(diffs) / len(diffs))
assert sum(b - a for _, a, b in pairs) == 0

4行すべてを列挙したので、この見本の条件では正確な値であり、信頼区間は不要。現実的な複数ターンのゲームで結果を試行から推定するときに区間を付ける。

6.2 複数ターン版に広げる手順

  1. 40枚にキー3枚を入れ、7枚を引く。取得率44.78%と照合する。

  2. 最小のゲームコアとルールベースAIを作り、基準と差し替えを2対面で回す。

  3. 先後を交換し、同じシード内にA/Bの4試合をまとめる。ログを1件再生する。

  4. 対面別に勝率・B−Aと、それぞれの区間を出す。先後やA/Bでシードを共有した設計では、どちらの区間も独立なブロック単位で推定する。取得した試合としなかった試合の比較は診断欄に分ける。必要なら「指定ターンまでは取得できない」という別介入を追加する。

  5. 変更の判断を、実務上の差の境界と照らす。結果が大きく変わった対面を別のAI・未使用シードで再確認する。

提出物の合格条件： 実験票、再実行コマンド、少なくとも1件のリプレイ、件数と区間のあるレポート、AIが不得意な戦略の明記。集計が正しくても、カードの面白さや理不尽さは人間のテストで別に見る。
