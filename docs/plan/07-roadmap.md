# 開発ロードマップ・MVP・最初の実験

## 19. 開発ロードマップ

Phase 1：評価理論の検証

目的：

統計的な評価指標を正確に計算できることを確認する。

実装：

- 取得確率
- ランダム効果
- 勝率
- 信頼区間
- 簡単な比較実験

Phase 2：基本シミュレーター

目的：

正確で再現可能な自動対戦を実現する。

実装：

- Game Core
- 20〜40種類の検証用カード
- 3〜5種類のデッキ
- ルールベースAI
- 乱数管理
- 対戦結果ログ

Phase 3：カード・デッキ評価

目的：

主要なバランス指標を算出する。

実装：

- カード差し替え評価
- デッキ勝率
- デッキ相性
- キーカード依存率
- 事故率
- ランダム効果の安定性

Phase 4：デッキ自動探索

目的：

人間が想定していない強いデッキを発見する。

実装：

- デッキ構築AI
- シナジー探索
- 予算制約付き探索
- レアリティ評価

Phase 5：分析ダッシュボード

目的：

評価結果を開発者が利用できる形で可視化する。

実装：

- カードTier
- デッキTier
- 相性表
- 依存率
- 予算別評価
- 調整前後の比較

Phase 6：高速化・実運用

目的：

自社ゲームの開発フローに組み込む。

実装：

- CPU並列化
- 性能測定
- 必要に応じたGPU計算
- 自動実験ジョブ
- 継続的なバランス検証

## 20. 初期MVP

最初のMVPでは、以下を達成する。

1. C#で自動対戦を実行できる。
2. ゲームの動作を再現できる。
3. デッキ勝率と相性を算出できる。
4. カード差し替え実験を実行できる。
5. キーカード依存率を算出できる。
6. デッキ事故率を算出できる。
7. ランダム効果の期待値・分散を評価できる。
8. 統計的な信頼区間を算出できる。
9. 分析結果をレポートとして出力できる。

次の機能は初期MVPの必須要件としない。

- GPU計算
- 深層強化学習
- 他社ゲーム対応
- 汎用SDK
- クラウド分散実行
- 完全自動のバランス調整

## 21. 最初の研究実験

実験テーマ

キーカード依存性の定量評価

実験目的

特定カードに依存しているデッキを、対戦シミュレーションによって正しく検出できるか検証する。

比較条件

デッキA

基本デッキ。

デッキB

キーカードを同じ役割の代替カードに変更したデッキ。

実験C

キーカードを指定ターンまで取得できない条件を与えた実験。

測定項目

- 総合勝率
- キーカード取得率
- 取得ターン別勝率
- 非取得時勝率
- カード差し替えによる勝率差
- 事故率
- 信頼区間

成功条件

- 同じ実験を再現できる
- 比較対象の条件を管理できる
- カード依存の大きさを測定できる
- 結果の不確実性を表示できる
- 評価結果の解釈上の限界を説明できる
