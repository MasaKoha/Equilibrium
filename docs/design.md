# 設計書

2026-11-21 時点。実装はまだ無い。ここに書くのは境界と、実装の前に決めた判断である。
評価指標の定義は[計画書](plan/README.md)にある。

## 1. 公開範囲の境界

このリポジトリ（public）にはゲームに依存しない部分だけを置く。
自社ゲームに固有のものは private リポジトリに置き、private が public を参照する。

```
private（未作成）                      public（このリポジトリ）
  自社ゲームのルール実装   ──参照──▶    Equilibrium.Core
  カードデータ                          Equilibrium.Simulation
  ルールベース AI                       Equilibrium.Storage
  実験の設定・評価レポート              samples/ToyGame
                                        python/
```

- 参照の向きは private → public の一方向だけ
- private を作るのは、自社ゲームのルールが実装できる程度に決まった時点
- それまでは見本ゲーム（`samples/ToyGame`）で、評価の計算と再現性を確かめる
- 汎用の探索（MCTS など）は public、盤面の評価関数は private。
  ルールベース AI しか無い間は、public に AI 用のプロジェクトを作らない

## 2. プロジェクトの責務

| プロジェクト | 責務 | 対象 |
|---|---|---|
| `Equilibrium.Core` | ゲームの契約（状態・合法手・適用・勝敗）、乱数、イベントとリプレイの型 | netstandard2.1 / C# 9 |
| `Equilibrium.Simulation` | 対戦の実行、並列、シードの割り当て、実験条件の記録 | net10.0 |
| `Equilibrium.Storage` | 試合結果・イベント・実験条件の書き出し | net10.0 |
| `samples/ToyGame` | 契約を実装する小さな見本ゲーム | netstandard2.1 / C# 9 |
| `python/` | 統計解析（推定・信頼区間・比較） | Python |

`Equilibrium.Cli`（実験を起動する入口）は、実行できる対戦ができた時点で足す。

## 3. 設計判断

### 判断 1: Core は netstandard2.1 / C# 9 にする

Unity のビューが同じ DLL を参照する。ルールを Unity 用にもう 1 つ書くと、
評価した対象と遊ばれる対象が別の実装になり、評価結果が当てにならなくなる。
実行側（Simulation・Storage）は Unity から参照しないので新しい .NET でよい。

### 判断 2: C# と Python はファイルでつなぐ

C# が Parquet と実験条件の JSON を書き、Python はそれを読むだけにする。
プロセス間の呼び出しは作らない。ゲームロジックを Python 側に持たない。

### 判断 3: Core は同期の純粋な関数にする

「状態と行動を受け取り、次の状態とイベント列を返す」関数として書く。

- リプレイは、初期状態・シード・行動列から再現する
- 解析はイベント列だけを読み、Core の内部の型に依存しない
- Core の中では Observable を使わない。1 試合の内部は 1 スレッドで順に進み、
  合成する流れが無い。試合数が増えると購読のアロケーションが実行時間に効く
- Rx.NET は実行側で、進捗とジョブの通知に使う

### 判断 4: 乱数は「シード・用途・何回目か」から値を計算する

乱数を用途（山札のシャッフル、効果の対象選択、AI の選択など）ごとに分ける。
各用途の n 回目の値を、シード・用途・n から直接計算する。

順に消費する乱数だと、カードを 1 枚差し替えただけで以降の値がすべてずれ、
差し替え前後の勝率の差に乱数の差が混ざる。この方式では、差し替えと関係のない用途の値は変わらない。
計画書 12.3 の共通乱数法をこれで成り立たせる。

アルゴリズムは未決（§4）。

### 判断 5: AI には、そのプレイヤーから見える情報の型だけを渡す

相手の手札と山札の順番を AI が読めると、AI の勝率が実際のプレイより高く出る。
全体の状態と、プレイヤーから見える情報を別の型にし、AI の入口は後者だけを受け取る。

### 判断 6: カードは数値をデータ、効果をコードで書く

効果の記述言語は作らない。同じ形の効果が並び、コードの重複が実際に問題になってから検討する。
